# 手机验证

测试 APK 可覆盖安装现有版本；保持同一签名。首次迁移会将供应商转入上游数据库，旧加密数据保留用于恢复。

1. 授权整个 Codex .codex，应用重启后仍可读取；撤销授权时能显示原因并重新选择。普通测试目录验证与已接通 Codex 分开记录。
2. 新增配置显示完整当前 TOML，含 MCP、项目和工作目录；编辑 API Key、模型、模型菜单、上下文和思考等级后保存。确认无旧“保留官方登录”选项。
3. Codex 开着时切换第三方和官方配置，再重启 Codex，确认实际供应商、模型和官方登录。钥匙串状态不能仅由目录判断。
4. 分别启用路由、故障转移、聚合；增删队列和成员，选择聚合默认与子代理模型；实际菜单使用 ccs- 模型 ID 并连接正确服务商。
5. 在路由、聚合选项卡下方开启“历史推理与ID过滤（解决不同源错误）”，出现后台限制提示；两种模式共用状态。确认仅查看页签或开启开关不会切换模式，回到直连后过滤暂停，配置表单没有此开关。息屏后台使用 Codex，工具 call_id 保持配对，SSE 可持续输出。加密压缩/跨源引用明确报错。
6. 用量脚本真实查询，查看路由和会话统计；重复刷新不重复计算。竖屏与用户手动横屏分别查看表格、图表和会话详情。
7. 导入导出、10 份滚动备份、恢复；短配置覆盖长配置不残留尾部。失败后不要把文件保存成功当成运行时确认。
8. 强制停止 CC Switch、系统杀后台和手机重启后，先重新打开应用；核对路由状态与 Codex 重启提示。
9. 覆盖安装 0.4.2 后检查重复的官方 default 自动并入 OpenAI Official；当前指针正确，第三方 default 和用户修改过的卡片保留。旧版已开启的过滤迁移到模式页，直连保持直连。

本仓库主机集成测试使用真实上游代码和模拟文档提供方，不能代替 Android ContentResolver、OEM 后台策略或真实 OAuth 验证。
