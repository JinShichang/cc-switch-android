# 手机测试步骤

本页的 SAF 与 Codex 实机步骤尚未执行。主机测试通过不等同于手机文件权限或 Codex 已生效。

## 先验证普通 SAF 目录

1. 在手机文件管理器创建一个专用空目录，例如 `Documents/CCSwitch-SAF-Test`，不要使用已有真实 Codex 数据目录。
2. 安装 `cc-switch-android-0.1.0.apk`，检查默认简体中文、200% 缩放。设置中输入 180%、235%，检查左右每次减/加 10%，随后恢复 200%。
3. 点击连接目录，选择该专用目录。系统需要确认“允许访问”。界面应标明“普通 SAF 目录 · 尚未接通 Codex”。
4. 把交付的 `saf-test-providers.json` 保存到手机，在“设置 → 导入方案”选择该文件。它包含两个无效示例服务和一个官方配置方案，不包含有效密钥。
5. 应用“SAF 测试 A”。应看到“文件保存成功，已读回核对”。在“当前”页查看 `custom`、`test-model-a`。外部文件管理器应能看到新建的 `config.toml`。
6. 应用“SAF 测试 B”。检查模型为 `test-model-b`、地址和 Key 已更换；短文件覆盖不能残留旧文件末尾。应用不会发起网络请求。
7. 回到“备份”恢复 A 之前的备份；检查读回结果正确。若恢复最初不存在文件的备份，config.toml 应被删除。
8. 关闭并重新打开 CC Switch；方案、缩放和目录授权应保留。重新启动手机并解锁，再次确认。

这一组全部完成后，只能记录“普通 SAF 测试目录真实读写通过”。

## 检查用户配置保护

将 `fixtures/saf-test-config.toml` 复制为测试目录中的 `config.toml`。它含示例 MCP、工作目录和多行字符串，均不指向手机的真实服务。

应用 A/B 后，用支持文本查看的文件管理器确认：

- `[mcp_servers.test_preserve]`、`[projects."/home/codex/workspace"]`、`cwd` 原样保留。
- 字符串中伪造的 `[model_providers.custom]` 不是实际 provider 表，不被误改。
- `auth.json` 若存在，文件内容没有变化。

不要把示例 MCP 配置用于真实 Codex 环境；它仅用于普通测试目录。

## 错误与恢复

- 取消系统目录/文件选择器：只取消操作，不报保存成功。
- 撤销目录授权或解除授权后应用：提示重新授权；不能自动变成普通路径访问。
- 将 config.toml 改成重复 `model` 或未闭合字符串：读取/应用应提示 TOML 错误，不覆盖原文件；仍可恢复已有备份。
- 在另一应用中修改文件，然后点击当前界面中的“应用”：应提示文件版本冲突，刷新后才能重试。
- 使用只读提供方：应显示授权/写入失败，而非成功。
- 写入中途关闭提供方/应用：重新打开时若存在 journal，提示先恢复。请只在专用测试目录测试中断。
- 导出默认无 Key：重新导入后要求补填密钥；明确勾选包含 Key 后导出，文件为明文，请勿分享。

## Codex DocumentsProvider 上线后

1. 保留普通测试结果，重新授权 Codex 在系统选择器提供的整个 `.codex` 目录。
2. 完全退出 Codex 的运行进程，读取当前配置，先将当前路由保存为方案。
3. 添加真实原生 Responses 服务，填写真实 Key 和模型，预览变更，应用并读回。
4. 重启 Codex，建立新会话，确认实际请求地址、模型及鉴权使用新方案，同时验证内置 MCP 和工作目录正常。
5. 官方登录如存储于钥匙串，在 Codex 内确认账号状态，必要时给方案选择“保留官方登录界面”。不要把目录读取成功当成钥匙串登录成功。
6. 切回已有官方登录方案并重启 Codex。验证原官方登录仍可用。

只有该组验证完成，才能记录“已接通 Codex”；是否无需重启热更新，需要单独的宿主能力验证。
